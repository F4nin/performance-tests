## 1. [КРИТИЧНО] Thread-safety `get_next_user()` — `result.py:80`

### Проблема

```python
def get_next_user(self) -> SeedUserResult:
    return self.users.pop(0)
```

`list.pop(0)` — операция **O(n)** и **не является атомарной** в многопоточной среде.
Locust запускает каждого виртуального пользователя в отдельном потоке, а `SeedsResult`
является общим объектом. Два потока могут одновременно вызвать `pop(0)` и либо получить
одного и того же пользователя, либо словить `IndexError`.

### Решение

Использовать `collections.deque` + `threading.Lock`:

```python
from collections import deque
import threading

_queue: deque[SeedUserResult] = Field(default_factory=deque, exclude=True)
_lock: threading.Lock = Field(default_factory=threading.Lock, exclude=True)

def model_post_init(self, __context):
    self._queue = deque(self.users)

def get_next_user(self) -> SeedUserResult:
    with self._lock:
        return self._queue.popleft()
```

### Источники

- `collections.deque` и метод `popleft()` — O(1) в отличие от `list.pop(0)`:
  https://docs.python.org/3/library/collections.html#collections.deque
- `threading.Lock` — примитив синхронизации для защиты разделяемых данных:
  https://docs.python.org/3/library/threading.html#threading.Lock
- Статья о thread safety в Python с примерами `Lock` + `deque`:
  https://realpython.com/python-thread-lock/
- GIL не спасает от гонок при составных операциях (check-then-act):
  https://docs.python.org/3/glossary.html#term-global-interpreter-lock

## 2. [ВЫСОКИЙ] Отсутствуют виртуальные карты — `plan.py` и `result.py`

### Проблема

В `SeedAccountsPlan` (`plan.py:33`) и `SeedAccountResult` (`result.py:26`) есть только
`physical_cards`, хотя в контрактах присутствует и `rpc_issue_virtual_card_pb2.py`.

### Решение

**`plan.py`:**
```python
class SeedAccountsPlan(BaseModel):
    count: int = 0
    physical_cards: SeedCardsPlan = Field(default_factory=SeedCardsPlan)
    virtual_cards: SeedCardsPlan = Field(default_factory=SeedCardsPlan)   # добавить
    top_up_operations: SeedOperationsPlan = Field(default_factory=SeedOperationsPlan)
    purchase_operations: SeedOperationsPlan = Field(default_factory=SeedOperationsPlan)
```

**`result.py`:**
```python
class SeedAccountResult(BaseModel):
    account_id: str
    physical_cards: list[SeedCardResult] = Field(default_factory=list)
    virtual_cards: list[SeedCardResult] = Field(default_factory=list)     # добавить
    top_up_operations: list[SeedOperationResult] = Field(default_factory=list)
    purchase_operations: list[SeedOperationResult] = Field(default_factory=list)
```

### Источники

- Контракты виртуальных карт в проекте:
  `contracts/services/gateway/cards/rpc_issue_virtual_card_pb2.py`

## 3. [СРЕДНИЙ] Нет валидации `count >= 0` — `plan.py:11,21,34,51`

### Проблема

```python
count: int = 0
```

Поле принимает отрицательные значения, что логически бессмысленно для плана сидинга.

### Решение

```python
from pydantic import BaseModel, Field

count: int = Field(default=0, ge=0)
```

Параметр `ge=0` означает "greater than or equal to 0". Pydantic выбросит `ValidationError`
при попытке передать отрицательное число.

### Источники

- Pydantic numeric constraints (`ge`, `gt`, `le`, `lt`):
  https://docs.pydantic.dev/latest/concepts/fields/#numeric-constraints
- `Field()` — полное описание параметров:
  https://docs.pydantic.dev/latest/api/fields/#pydantic.fields.Field

## 4. [НИЗКИЙ] Нет защиты от пустого списка — `result.py:70,82`

### Проблема

```python
def get_next_user(self) -> SeedUserResult:
    return self.users.pop(0)  # IndexError если список пуст

def get_random_user(self) -> SeedUserResult:
    return random.choice(self.users)  # IndexError если список пуст
```

В контексте нагрузочного теста это приводит к падению Locust-воркера без понятной причины.

### Решение

```python
def get_next_user(self) -> SeedUserResult:
    if not self.users:
        raise RuntimeError("SeedsResult: нет доступных пользователей")
    return self.users.pop(0)

def get_random_user(self) -> SeedUserResult:
    if not self.users:
        raise RuntimeError("SeedsResult: нет доступных пользователей")
    return random.choice(self.users)
```

### Источники

- `random.choice` — бросает `IndexError` на пустой последовательности:
  https://docs.python.org/3/library/random.html#random.choice
- `list.pop` — бросает `IndexError` если список пуст:
  https://docs.python.org/3/tutorial/datastructures.html#more-on-lists
- Паттерн "fail fast" — лучше явное исключение, чем неявный сбой:
  https://en.wikipedia.org/wiki/Fail-fast_system
