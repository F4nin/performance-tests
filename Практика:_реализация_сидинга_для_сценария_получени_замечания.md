**Проблема:** Скомпилированный бинарный файл Python (байткод) закоммичен в репозиторий. **Рекомендация:**

```

*.py[cod]
*.pyo
*.pyd

```

## seeds/scenarios/existing_user_get_operations.py: строки 5–18

**Проблема:** Новый класс `ExistingUserGetOperationsSeedsScenario` и его свойства не имеют docstring. Это нарушает стиль, принятый в проекте: все остальные сценарии (`existing_user_make_purchase_operation.py`, `existing_user_get_documents.py`) снабжены docstring для класса и каждого метода/свойства.

Текущий код:
```python
class ExistingUserGetOperationsSeedsScenario(SeedsScenario):
    @property
    def plan(self) -> SeedsPlan:
        return SeedsPlan(...)
```

**Рекомендация:** Добавить docstring в соответствии со стилем остальных сценариев:
```python
class ExistingUserGetOperationsSeedsScenario(SeedsScenario):
    """
    Сценарий сидинга для существующего пользователя, который просматривает историю операций.
    Создаёт 300 пользователей, каждому открывается кредитный счёт с набором операций.
    """

    @property
    def plan(self) -> SeedsPlan:
        """
        План сидинга: 300 пользователей, у каждого кредитный счёт
        с 1 пополнением, 5 покупками и 1 снятием наличных.
        """
        return SeedsPlan(...)
```

**Источник:** [PEP 257 — Docstring Conventions](https://peps.python.org/pep-0257/)

## seeds/scenarios/existing_user_get_operations.py: строки 10–16

**Проблема:** Магические числа `count=300`, `count=5`, `count=1` используются без объяснения. В других сценариях проекта эти значения сопровождаются инлайн-комментариями (например, `# Количество пользователей`, `# Количество счётов на пользователя`). Без комментариев неясно, почему для `purchase_operations` выбрано именно 5 операций — возможно, это связано с тестированием пагинации или размером страницы в API.

Текущий код:
```python
count=300,
credit_card_accounts=SeedAccountsPlan(
    count=1,
    top_up_operations=SeedOperationsPlan(count=1),
    purchase_operations=SeedOperationsPlan(count=5),
    cash_withdrawal_operations=SeedOperationsPlan(count=1),
)
```

**Рекомендация:**
```python
count=300,  # Количество пользователей
credit_card_accounts=SeedAccountsPlan(
    count=1,  # Количество кредитных счётов на пользователя
    top_up_operations=SeedOperationsPlan(count=1),
    purchase_operations=SeedOperationsPlan(count=5),  # 5 покупок для проверки выборки
    cash_withdrawal_operations=SeedOperationsPlan(count=1),
)
```

**Источник:** [Clean Code, Robert C. Martin — глава 2: Meaningful Names](https://www.oreilly.com/library/view/clean-code-a/9780136083238/)

## dumps/existing_user_get_operations_seeds.json

**Проблема:** Генерируемый файл с тестовыми данными (357 KB, 12 304 строки) хранится в git. Это создаёт ряд проблем:
- История репозитория растёт при каждой регенерации (даже если логика не изменилась).
- Дифф нечитаем: 12 000 строк JSON при изменении одного параметра в `plan`.
- Файл — артефакт: он полностью воспроизводится запуском `existing_user_get_operations.py`.

При этом другие дампы из предыдущих коммитов имеют ту же проблему — это системный вопрос для всего проекта.

**Рекомендация:**
- Добавить `dumps/*.json` в `.gitignore`.
- Генерировать дампы локально или в CI как часть подготовки тестового окружения.
- Если файлы необходимо версионировать (например, для воспроизводимости), рассмотреть [Git LFS](https://git-lfs.com/).

**Источник:** [Git documentation — Ignoring Files](https://git-scm.com/book/en/v2/Git-Basics-Recording-Changes-to-the-Repository#_ignoring)
